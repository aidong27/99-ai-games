# Protocol 99 v1 — 规范提示词中文参考译本

> **非权威译本。** 本文件只方便中文读者理解，不参与 Canonical
> Prompt Hash，也不能用于正式 Run。正式基准唯一有效文本是
> [`PROMPT.md`](./PROMPT.md)。

为 Protocol 99 基准制作一款完整、原创、自包含的 2D 浏览器游戏。实现必须位于仓库自动化分配的 Run 目录中。

## 玩家角色

玩家控制一台位于受损中继设施中的维修无人机。

## 核心目标

竞技场中必须包含：

- 恰好三个可搬运的数据核心；
- 恰好三个未激活的中继节点；
- 一个锁定的撤离出口。

玩家一次最多携带一个数据核心。激活中继时，玩家必须把核心运送至中继并执行明确的交互；激活会消耗所携带的核心。全部三个中继激活后，撤离出口必须解锁。玩家只有亲自移动并进入已解锁出口才算获胜。

## 必需游戏系统

1. 紧凑俯视竞技场中的实时二维移动。
2. 从零到明确定义最大值的机体完整度。
3. 完整度归零时进入清晰的失败状态。
4. 至少两种行为有实质差异的危险；仅换颜色不算。
5. 恰好一种主要主动能力，例如冲刺、护盾、脉冲、诱饵或扫描。
6. 主动能力必须有冷却、能量、次数、风险或站位等真实限制。
7. 随零、一、二、三个中继激活而可观察到的世界阶段。
8. 每次中继激活都必须实质改变玩法或可玩世界；仅文字、加分或换色不算。
9. 可见的锁定出口与解锁撤离状态。
10. 无需刷新标签页即可重新开始的完整循环。

## 规模预算

初次玩家的成功通关目标约为三至八分钟。实现应聚焦于一个主要竞技场或紧凑连通地图；不得加入战役、多关卡、在线多人、后端、账户、外部 AI API、大型对话树、升级树，或核心搬运以外的库存系统。除必需系统外，最多增加一个主要特色机制，且不能取代或掩盖固定核心循环。

## 必需界面状态

游戏必须提供标题/开始、简洁控制与目标说明、游戏 HUD、暂停、胜利、失败和重开。HUD 必须清楚显示完整度、是否携带核心、中继激活数、主动能力状态以及撤离出口是否锁定。

## 标准控制

- 移动：WASD 和方向键；
- 交互：E；
- 主动能力：空格或 Shift；
- 暂停：Escape 或 P；
- 胜负后重开：R 和可见按钮；
- 菜单和可见按钮支持指针输入。

触屏玩法可选，但页面在 390 × 700 视口下不得横向溢出或无法使用。桌面玩法是基准要求。

## 可访问性基线

必须有可见键盘焦点，不能只用颜色传达关键信息，文字对比度应可读，支持 `prefers-reduced-motion`；若有音频则必须有静音控件；不得快速闪烁。

## 确定性

游戏必须支持确定性基准种子。URL 含 `?seed=99` 时，重复运行必须产生相同初始状态和危险行为。无种子时可使用随机行为，但基准路径固定使用 99。

## 浏览器测试契约

页面必须暴露只读接口 `window.__P99__`，其中 `contractVersion` 为
`"1.0"`，并提供 `getState()`。返回值必须是普通可序列化对象，至少包含：

```js
{
  phase: "title" | "playing" | "paused" | "won" | "lost",
  seed: 99,
  integrity: number,
  maxIntegrity: number,
  carryingCore: boolean,
  coresCollectedTotal: number,
  relaysActivated: number,
  worldStage: number,
  abilityStatus: "ready" | "cooldown" | "unavailable",
  exitUnlocked: boolean,
  elapsedMs: number
}
```

该接口必须反映真实游戏状态，不能提供自动获胜、直接改状态、测试传送、无敌或其他绕过正常玩法的能力。重要状态变化后必须派发
`protocol99:statechange` CustomEvent。

适用的可见元素必须使用：

```text
data-p99-action="start"
data-p99-action="pause"
data-p99-action="restart"
data-p99-ui="instructions"
data-p99-ui="hud"
data-p99-ui="victory"
data-p99-ui="defeat"
```

## 通关证据

实现必须提供确定性 Playwright 测试，覆盖开始、暂停/继续、重开、真实失败，以及通过公开玩家控制完成真实通关。测试只能通过仓库提供的只读 SDK 读取状态，不能修改内部状态、调用隐藏函数、传送、注入胜利、禁用危险或使用测试作弊。

## 技术约束

- 从本地静态 HTTP 服务器运行。
- 运行时代码仅使用本地 HTML、CSS、JavaScript、Canvas、SVG、DOM 或 Web Audio。
- 不得发起远程网络请求。
- 不得使用运行时 npm 依赖或第三方 CDN。
- 不得嵌入远程 iframe。
- 不得使用受版权保护的系列角色、标志、音乐或复制素材。
- 不得使用 `eval`、`new Function`、远程动态导入、Service Worker 注册、WebSocket、EventSource 或外部分析。
- 已提交的游戏运行时总大小应低于 5 MiB；例外必须由验证器记录合理理由。
- 加载时不得出现未捕获控制台错误。
- 同一标签页重开并连续游玩两局时，不得重复创建循环、控件、定时器或事件监听。

## 创作自由

可以自由选择视觉语言、设定细节、竞技场布局、危险设计、主动能力、动画风格、本地程序视觉、本地生成音效、副标题、叙事风味和一个可选主要特色，但必须保持固定目标与规模。

## 完整性规则

不得检查、复制、导入或改编以前基准 Entry 的游戏源码。不得修改基准定义、其他 Entry、其他 Run 或 Legacy 游戏源码。不得伪造截图、测试报告、模型身份、通关证据或来源。此 Run 的全部游戏实现必须位于自动分配目录内。只有在完成实现、确定性浏览器测试、仓库验证并修复自身失败后，才能 Finalize。
